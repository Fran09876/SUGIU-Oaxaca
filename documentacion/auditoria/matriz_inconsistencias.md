# MATRIZ DE INCONSISTENCIAS Y CONTRADICCIONES DETECTADAS

**Fecha de Auditoría:** Noviembre 2026  
**Objetivo:** Identificar discrepancias entre la documentación previa, los requisitos declarados y la implementación real en el código fuente de SIGIU.

---

## 1. Matriz Comparativa de Inconsistencias

| Área de Evaluación | Declaración en Documentación / README Previo | Realidad Técnica Comprobada en Código | Grado de Impacto | Corrección Aplicada en la Nueva Documentación |
| :--- | :--- | :--- | :--- | :--- |
| **Arquitectura Frontend y PWA** | Se define reiteradamente a SIGIU como una *"Progressive Web App (PWA) Móvil"* nativa o instalable con soporte sin conexión. | El cliente web posee únicamente un archivo `manifest.json` estático. No existe Service Worker registrado, no se utiliza la Cache Storage API ni librerías como Workbox, y no hay persistencia offline. | **Alto** | Se rectifica la terminología técnica: SIGIU es formalmente una **Plataforma Web Responsiva** accesible desde navegadores móviles y de escritorio. |
| **Paleta Cromática Institucional** | El `README.md` describe la paleta de las iteraciones 0-2: Royal Blue (`#112250`), Sapphire (`#3C507D`), Quicksand (`#E0C58F`), Swan Wing (`#F5F0E9`) y Shellstone (`#D9CBC2`). | El archivo `tailwind.config.js`, los estilos en `index.css` y todos los componentes React utilizan la paleta oficial actualizada: Charcoal Dark (`#151719`), Slate Gray (`#3F4B48`), Medium Gray (`#7D8181`), Soft Slate (`#A9AFB2`) y Lotus White (`#D0D4D7`). | **Medio** | Se actualiza la especificación de diseño visual en toda la documentación técnica reflejando los valores hexadecimales activos. |
| **Alcance de Iteraciones Declaradas** | El `README.md` declara un alcance limitado a las *"Iteraciones 0, 1 y 2"*. | El código fuente contiene la implementación completa y funcional de las **Iteraciones 0 a 5** (Despacho del Operador, Órdenes de Trabajo, Analítica, Visor GIS y App de Campo para Cuadrillas). | **Alto** | Se documentan de forma integral y estructurada las Iteraciones 0, 1, 2, 3, 4 y 5, mostrando el ciclo de vida completo del sistema. |
| **Implementación Geoespacial (PostGIS)** | Se afirma el uso estricto de columnas `GEOMETRY(Point, 4326)` con índices espaciales `GIST` y triggers espaciales obligatorios. | El modelo Sequelize (`Report.js`) persiste coordenadas en columnas decimales (`latitud DECIMAL(10,8)` y `longitud DECIMAL(11,8)`) con un campo JSON para GeoJSON. La base de datos local de PostgreSQL emite advertencia de que la extensión PostGIS no está habilitada. | **Alto** | Se explica con transparencia que el sistema opera con coordenadas geodésicas WGS84 decimales y GeoJSON estándar (RFC 7946), dejando PostGIS nativo como una capacidad soportada en el DDL pero no mandatoria en tiempo de ejecución. |
| **Metodología XP: Pair Programming** | Se indica la aplicación de la práctica de *"Programación en Pareja"* (Pair Programming) de Extreme Programming. | El proyecto fue desarrollado de manera individual por el estudiante José Francisco Pérez Pérez en el marco de la asignatura Desarrollo Web con Enfoque Ágil en el ITO. | **Medio** | Se aclara que la práctica de programación en pareja no fue aplicable debido a la modalidad de trabajo individual, explicando las adaptaciones realizadas a la metodología XP. |
| **Metodología XP: Práctica TDD** | Se declara desarrollo guiado por pruebas (Test-Driven Development) donde las pruebas se escribieron antes del código. | La suite de pruebas (`server/tests/api.test.js`) se diseñó como pruebas de integración y validación a posteriori sobre endpoints y modelos existentes para asegurar regresión, sin evidencia de ciclo Red-Green-Refactor previo. | **Medio** | Se documentan las 9 pruebas existentes como pruebas de integración y aceptación técnica, reconociendo la ausencia de un ciclo formal previo de TDD. |
| **Integración Continua (CI/CD)** | Se menciona integración continua en el marco metodológico de Extreme Programming. | No existen pipelines automatizados configurados en el repositorio (no hay carpetas `.github/workflows`, `.gitlab-ci.yml` ni configuración de Jenkins). | **Medio** | Se clasifica la integración continua como una práctica parcialmente adaptada a nivel local mediante scripts npm (`npm test` y `npm run build`), recomendando un pipeline formal como trabajo futuro. |
| **Convenio y Estatus Institucional** | El sistema se presenta como una plataforma municipal oficial implementada y operada por el Ayuntamiento de Oaxaca de Juárez. | SIGIU es un proyecto de desarrollo de software con fines académicos y de titulación en el Instituto Tecnológico de Oaxaca (TecNM), sin convenio formal suscrito ni despliegue oficial por el municipio. | **Alto** | Se define a SIGIU con rigor académico como un **prototipo funcional de propuesta tecnológica** contextualizado en las necesidades del Municipio de Oaxaca de Juárez. |
| **Almacenamiento de Evidencias Fotográficas** | Se sugiere persistencia distribuida o segura de archivos de alta disponibilidad. | Multer almacena los archivos en el sistema de archivos local (`server/uploads/`). En caso de despliegue en contenedores efímeros sin volúmenes montados, los archivos se perderían. | **Medio** | Se documenta el almacenamiento local en disco, señalando el riesgo técnico y proponiendo la migración a almacenamiento en la nube (S3/Cloudinary) como mejora prioritaria. |
| **Notificaciones y Tiempo Real** | Se mencionan "notificaciones automáticas a cuadrillas y ciudadanos". | Las vistas dependen de sondeo o actualización bajo demanda al recargar o entrar a la vista. No existen WebSockets (Socket.io) ni Server-Sent Events (SSE) implementados. | **Medio** | Se describe el mecanismo real basado en peticiones HTTP periódicas y actualización bajo demanda en la interfaz de usuario. |
